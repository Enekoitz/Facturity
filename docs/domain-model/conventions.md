# Conventions

General conventions or rules about Facturity domain model.

| Convention / Rule                                                                                                                                                                                                          | Reason                                                                                                                                       | Notes                                                                                                                                                                                                                | Creation At | Updated At |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ---------- |
| An aggregate root cannot have a navigation property pointing to another aggregate root within the system, even if both exist within the same context or module. The relationship is established solely via the identifier. | This creates excessive coupling between aggregate roots. Since Facturity is a modular monolith, we aim to decouple the system appropriately. | - In certain cases, it is necessary to conduct a specific assessment and document the reasons for such decisions; however, this is only appropriate if the advantages outweigh the disadvantages and are compelling. | 2026-11-07  |            |
